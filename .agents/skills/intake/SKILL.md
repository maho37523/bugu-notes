# 需求整理

以项目根 [AGENTS.md](../../../AGENTS.md) 为统一规则入口；开工、任务格式、版本保存和交接遵循其引用规范，本 Skill 只补充需求整理。

1. 读取用户原话和关联任务，对照当前产品边界、工程状态及实际代码确认现有能力；区分 Android 实现、Web 演示、历史规划和未确认事实。
2. 明确用户问题、目标行为、范围与不做项。将可观察的结果写成验收条件，覆盖关键正常路径、失败路径及兼容风险；不预定架构或添加未经请求的功能。
3. 优先查证工程可回答的问题；对影响产品取舍或验收的缺口提出最少必要问题。暂用假设时明确标注，不能代替用户确认。
4. 按现有任务格式在 `docs/exec-plans/` 查重后新建或补充任务并更新索引。保存原始诉求、现状证据、需求、验收条件、风险、待决定事项，以及需求确认与实施授权各自的依据；未确认不标为已确认。整理完成不等于产品验收或实施许可。

输出任务链接与需要确认的差异；到此结束，不修改业务代码或自动进入开发。若请求实际是修复既有行为，归入 bugfix；若是实施已确认新能力，归入 feature；若只要求检查，归入 review。按本次用户意图选择流程，不串行自动调用其他 Skill。
