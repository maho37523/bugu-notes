# 故障修复

以项目根 [AGENTS.md](../../../AGENTS.md) 为统一规则入口；开工、版本保存、质量检查和交接遵循其引用规范，本 Skill 只补充故障诊断与修复。

1. 读取故障描述、关联任务、产品规范及实际代码，明确预期与实际行为、触发步骤、环境和影响。若预期本身需要产品决定，先记录待决定事项；不能把新能力伪装成修复。
2. 核对本次修复授权及当前阶段允许的范围。当前仅工程基础时，不能据此修改业务行为；可继续获准的静态诊断和方案准备，记录阻塞条件。真实数据、启动与恢复等操作按项目既有边界执行。
3. 在允许的隔离环境和合成数据中复现，区分产品、环境、测试夹具或旧产物问题，保留失败证据；未复现时标为未确认，说明下一条查证动作，不猜测根因后盲改。
4. 沿故障链定位根因，选择能恢复既有约定的最小修复。补充能在修复前揭示失败、修复后通过的回归断言；无法自动化时给出可重复验证与限制。不得通过删除断言或扩大重构掩盖问题。
5. 重新执行复现场景及质量矩阵要求的相关回归，记录修复前后结果、覆盖限制和遗留风险。范围外问题单独登记，不纳入本次修复。

输出故障证据、根因、修复范围与回归结果；未证实或受阻的部分保留明确状态。若只要求诊断或报告而未要求修复，使用 review；有意改变既有约定的新能力归 feature；尚待整理的新需求归 intake。
