# 独立检查

以项目根 [AGENTS.md](../../../AGENTS.md) 为统一规则入口；开工、质量检查、版本保存和交接遵循其引用规范，本 Skill 只补充审查流程。

1. 确定审查对象、代码基线与范围；读取关联任务的验收条件、产品规范和当前实现。检查全项目还是具体变更以用户要求为准；变更审查区分新增问题与既有风险。
2. 独立沿实际代码链核对行为、边界和兼容性，不把作者说明、历史通过记录或模拟 UI 当作正确性证据。“独立”指重新查证结论，不默认另启会话或代理。
3. 按质量矩阵选择获准检查，在隔离副本中使用合成数据验证；必要复现资料放隔离环境。默认不修改业务代码、产品规范或共享测试文件；发现问题只提出修复建议，不顺手实施。
4. 按影响排序报告可行动缺陷：给出位置、触发条件、预期与实际结果、影响及证据；不能证实的怀疑列为待查风险，不混为已确认缺陷。列出实际测试、失败/跳过/受阻原因及未覆盖场景；没有发现时明确审查范围和验证限制。
5. 将结论保存在现有任务的审查记录，或按现有格式新建审查任务并更新索引。技术审查结论不替代用户体验验收，不改变被审任务的需求确认或实施授权。

输出报告链接、主要缺陷、实际测试结果和风险。用户后续明确要求修复时，重新核对授权后使用 bugfix；新增能力使用 feature；需求整理使用 intake。本流程默认止于报告。
