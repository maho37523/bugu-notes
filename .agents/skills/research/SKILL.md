# 技术研究

以项目根 [AGENTS.md](../../../AGENTS.md) 为统一规则入口；开工、任务记录、版本保存和交接遵循其引用规范，本 Skill 只补充技术调查。

1. 明确研究问题、候选方案和决策所需证据，读取关联需求、当前架构与相关代码/版本。需求有缺口时记录假设与适用范围；仅当缺口阻止有效调查时询问，不自行确认产品需求。
2. 检索并实际打开官方文档、发布说明、官方仓库及适用授权/许可说明，优先当前有效的一手资料。记录来源链接、核查日期、文档或产品版本、适用平台与账号范围；比较最新能力与本项目当前所用版本，不将新版本能力当作当前已支持。搜索摘要和第三方经验仅作线索；无官方证据、资料冲突或无法访问时明确待确认，不以“未找到”推断禁止或不可行。
3. 按相关维度比较合理候选（包括沿用现有实现）：需求满足度、接入与兼容成本、维护状态、授权/计费限制、数据与凭据风险及验证缺口。将“已确认事实”（带来源或代码证据）、“推测”（说明依据）、“待确认事项”（说明查证方式）分开。官方声明、静态代码结论与实际实验结果分别标明，不能相互替代。
4. 如有必要且已获准，才在隔离环境用合成数据做最小验证，记录环境、步骤和结果。研究请求不授权改业务代码、安装依赖、登录账号、使用真实凭据、付费调用或开展功能原型；缺少相应授权时报告缺口，继续不受影响的资料调查。
5. 将报告保存到 `docs/exec-plans/T-YYYYMMDD-主题-research.md`（先查重），按现有任务格式登记并更新索引，链接关联需求；已有专门研究任务则更新原报告。报告至少包含研究问题与工程基线、带日期/版本的来源与三类结论、方案比较、建议及理由、风险/阻塞、未验证项和后续可执行查证步骤。结论摘要与关键证据留在项目文件，不仅保存在聊天或临时目录；研究建议不直接写成已采纳的 ADR 或产品承诺。

发现技术不可行、授权限制或重大风险时，及时先向用户说明依据、影响、尚不确定之处和需要决定的选项，并写入报告；停止依赖该条件的试验或实施，不等待整份报告完成才披露。可继续独立且已授权的调查，不绕过限制或自行切换方案开发。

输出报告链接、可行性结论、主要风险与待决定项；流程止于研究，不自动进入实施。需求与验收整理归 intake，已有代码符合性/缺陷检查归 review，修复归 bugfix，获准的新功能实施归 feature。研究报告不构成需求确认或开发授权。
