## 2. 调研结论

### 2.1 ChatGPT Projects 的可借鉴逻辑

ChatGPT 的项目不是文件夹，而是**一个持续上下文容器**：

- 项目里放 **chats / files / instructions**；项目指令只在该项目生效，并覆盖全局指令。
- 项目可以选 **default memory** 或 **project-only memory**；project-only 下不引用项目外记忆，项目外也不能引用项目内对话。
- 对话可以移入/移出项目；移入后继承项目的指令和文件上下文。
- 可以把一条回答“Add to project sources”，以后作为资料复用。
- 项目内可以搜索历史对话、创建新对话、分支对话。

映射到我们的产品：

```
Workspace
 ├── Project（名称/图标/项目指令/记忆策略）
 │    ├── 对象：Note / Chat（每个对象只有一个归属项目）
 │    ├── 资料：笔记、附件（可被项目内对话检索）
 │    └── 记忆：默认 / 仅项目
 ├── Inbox（未归属项目的笔记和聊天）
 └── Trash（笔记）/ Archive（聊天）
```

不建议把 Project 做成多文件夹：**对象只有一个归属项目**，标签和 `[[链接]]` 可以跨项目；跨项目引用必须显示来源，避免上下文串味。

### 2.2 Typora 的真实形态

Typora 不是“源码 + 右侧预览”，而是 **live preview / 单栏内联渲染**：非活动内容直接以排版后的形式显示，光标进入时露出 Markdown 标记。这和我们现在的“编辑/预览切换 + 平板分屏”是两种编辑器内核。

因此 #11 不是加一个预览面板，而是三条路线选一条：

| 路线 | 效果 | 成本 | 风险 |
| --- | --- | --- | --- |
| A. 源码 + 分屏/同步滚动 | 接近普通 Markdown 编辑器 | 低 | 不是 Typora，手机上仍挤 |
| B. 单栏混合编辑（块渲染，点按编辑） | 最接近 Typora | 高 | 选区、IME、跨块撤销、粘贴要重做 |
| C. WebView + CodeMirror/ProseMirror | 快，功能全 | 中 | 与 Compose 主题、AI 选区、原生交互割裂 |

建议：**先做 A 的同步滚动，B 单独立项做 spike，确认后再替换编辑器内核；不要把它和项目/远端功能混在一个版本。**

### 2.3 电脑 DSH 的接入面

我检查了本机 DSH 的 `dsh web --help` 和打包内的 remote-access 文档，确认它不是只能开网页：

- `dsh web` 可以绑定本机某个具体 IP、指定端口、TLS 证书和 `--trusted-host`；不接受 wildcard 绑定。
- 浏览器/客户端先用 launch token 换签名 Cookie；API 客户端走 `GET /connect?token=...&interactions=answer|none` 换取 API Cookie 和 mux 地址。
- 远程调用走 `/api/remote.mux` WebSocket；普通 RPC 是 HTTP POST。
- Cookie 绑定 host/port，HTTP 下没有 `Secure`；**局域网明文会泄露 bearer cookie**，必须 TLS 或安全隧道。
- 这是 DSH 的内部接口，不是公开稳定 API；需要版本/能力握手和适配层。

结论：**#12 和 #13 是同一个工作流**——手机是控制面，电脑 DSH 是执行面；手机不下载工具链、不构建，只负责编辑、发指令、收结果和附件。配对建议二维码/配对码，手机换 Cookie 后加密保存，断线重连，桌面可撤销设备。

### 2.4 状态栏割裂的代码原因

当前 `DshApp` 在手机和宽屏都把 `safeDrawingPadding()` 加在整个 `mainContent` 外层：

- 状态栏区域被让出来，显示的是 Activity 的 window background；
- 顶栏从状态栏下面才开始，和状态栏之间形成一条“背景带”；
- 系统对比度 scrim/不同 ROM 的 window background 会放大这条带。

修复方向不是再加 padding，而是：
1. 根布局背景画到状态栏后面；
2. 只给顶栏内容加 `statusBars` inset；
3. 状态栏透明、图标明暗跟随主题、关闭对比度强制；
4. 刘海/挖孔用 `displayCutout` 安全区，不用整体 `safeDrawingPadding`。

## 3. 产品逻辑（建议定稿）

### 3.1 项目是上下文单位，不是文件夹

- 一个笔记/聊天只属于一个 Project；默认进入 `Inbox`。
- 项目有：名称、图标/颜色、项目指令、记忆策略（默认/仅项目）、绑定的 DSH 工作区（可选）。
- 项目内对象列表：笔记 / 对话 / 资料；可互相引用。
- 移动对象 = 改变归属；不复制内容；跨项目引用只生成引用，不搬运上下文。

### 3.2 只有一个 AI 入口

按 #10，删除笔记编辑器里的 AI。AI 只存在于对话：

- 笔记里选中文本 → “在对话中提问 / 引用到对话”，跳到对话并带 quote chip；
- 对话里 `@` 或 `[[` 引用笔记；
- AI 的写操作只以“建议卡”出现：新建笔记 / 追加到笔记 / 替换选区（需确认）；
- 笔记版本在应用建议前自动保存。

这样 #7（AI 读笔记）和 #10（删掉笔记 AI）不矛盾：**AI 读笔记，但不驻留在笔记编辑器里。**

### 3.3 上下文必须显式

每次发送前显示 chip：
`引用笔记《X》· 2.3k 字`、`引用消息 #12`、`项目资料 3 篇`、`记忆 2 条`。
点开可移除。默认只带：
- 项目指令；
- 用户显式引用的笔记/消息；
- 项目内检索到的少量片段（不是整个笔记库）；
- 明确启用的记忆。

### 3.4 记忆是独立数据，不是笔记全文

- 记忆类型：用户偏好、长期事实、项目决策。
- 作用域：全局 / 项目；项目可设“仅项目记忆”。
- AI 只能建议“记住这条”，用户确认后入库；记忆中心可编辑、停用、删除。
- 笔记可以被标记为“项目资料”，但不会自动变成记忆。

### 3.5 版本与自动保存分开

- 当前正文 = 工作副本，500ms 自动保存；
- 手动“保存版本”输入名称，生成 `v1 / 方案定稿`；
- 自动检查点：每 10 分钟或有风险的 AI 写入前；
- 历史面板可预览、diff、恢复；恢复本身生成新版本，不覆盖历史；
- 版本号按笔记自增，名称可空。

### 3.6 生命周期

- 笔记删除 → 垃圾桶；可恢复/永久删除/清空；30 天清理。
- 聊天删除 → 归档；可取消归档；归档不删除消息。
- 批量：笔记批量移入垃圾桶；聊天批量归档；永久删除只发生在垃圾桶/归档页，必须二次确认。
- 所有批量操作有选择态 action bar 和结果 toast/undo。

### 3.7 远端执行边界

- 手机端永远不提供“完全访问”或本地构建。
- 执行目标二选一：`本机模型`（仅文本对话/笔记问答）或 `电脑 DSH`（工具、文件、构建）。
- 权限用范围表达：`只读` / `可写项目` / `可执行构建`；危险操作在桌面端确认。
- 手机断网时只读缓存；恢复后重连，不重放高危操作。

## 4. 实现链路

### Stage 0：数据地基（阻塞所有后续）

1. `projects` 表 + `notes.project_id` + `chat_sessions.project_id`。
2. 聊天从 `DshApp` 内存迁到 Room：`chat_sessions` / `chat_messages`（content parts）。
3. `attachments` 表 + 私有文件目录 + 草稿/上传状态。
4. `note_revisions` 升级：版本号、名称、manual/auto、来源、diff 基础。
5. `memories` 表 + 作用域。
6. 根布局/状态栏修复、全文复制（小改动，先做）。

验收：杀进程重开，项目/笔记/对话/附件状态都在；项目筛选正确。

### Stage 1：编辑器与生命周期

1. 成对符号：自动配对 + 成对退格 + 组合态保护 + 单测。
2. 编辑器分类下拉底部“新建分类”，创建后选中。
3. 版本历史：手动命名、自动检查点、列表、预览、恢复。
4. 垃圾桶/归档/批量选择/二次确认。
5. 笔记全文复制、整段对话复制。

验收：`**`、`[]`、`()`、`[[]]` 的配对删除测试通过；版本可恢复；批量删除必须二次确认。

### Stage 2：项目与 AI 上下文

1. 项目页：对象列表、项目指令、记忆策略、资料。
2. 删除笔记内 AI。
3. `[[` 在对话中自动补全 + 消息内可点击引用。
4. 选中 AI 文本引用到下一轮（quote chip + quoted_message_id）。
5. 记忆建议/确认/记忆中心；上下文 chip。
6. `search_notes`/`read_note` 工具（本机检索或 DSH 工具），项目范围优先。
7. 笔记内“在对话中提问”入口。

验收：对话能明确看到引用了哪篇笔记/哪条消息/哪条记忆；未配置 API 不伪造回答。

### Stage 3：附件管线

1. SAF/相册/相机选择；复制到私有目录；缩略图/大小/MIME。
2. 聊天消息 content parts：文本 + 图片 + 文件。
3. 图片视觉请求；PDF/Office 文本提取；不支持类型明确提示。
4. 笔记图片插入相对路径、附件卡片、预览。
5. 上传/失败/重试/删除；远端 DSH 上传。

验收：从相册选一张图，消息里可见并真正进入模型请求；PDF 能提取文本；重启后附件还在。

### Stage 4：电脑 DSH

1. `remote_hosts` 表：地址、证书指纹、加密 Cookie、能力、最后在线。
2. 配对：桌面显示二维码/配对码；手机走 `/connect` 换 Cookie；TLS/指纹校验。
3. 连接管理：能力握手、心跳、断线重连、撤销设备。
4. 项目绑定 DSH 工作区；笔记 Markdown 推送/拉取；附件上传。
5. 远程会话：发送 → 流式事件 → 工具/构建 → 产物下载。
6. 权限范围 + 桌面确认；删除“完全权限”。

验收：手机发一句“构建并运行”，电脑执行，手机收到日志/产物；手机关网不执行高危操作；桌面可撤销。

### Stage 5：Typora 式编辑器（独立里程碑）

1. 选型 spike：单栏混合 vs WebView/CodeMirror vs 分屏增强。
2. 若选单栏混合：块解析、活动块源码、跨块选区/复制/撤销、IME、粘贴。
3. 与现有版本/附件/双链/搜索打通。
4. 保留源码模式作为回退。

验收：在手机上边写边看到排版结果；光标进入块时显示 Markdown；跨块复制/撤销不丢内容。

## 5. 需要你拍板

1. Project 归属：一个对象只属于一个项目（推荐），还是允许多项目？
2. 项目记忆：默认 project-only（推荐，隐私清晰），还是允许引用全局记忆？
3. Typora：先做“分屏 + 同步滚动”（快），还是直接立项单栏混合编辑器（接近 Typora，但周期长）？
4. 电脑 DSH：接受内部 API + 版本适配（功能完整但可能随 DSH 升级变化），还是先用 WebView 打开 DSH Web UI（稳但不够原生）？
5. 附件 P0：图片/PDF/文本优先（推荐），Office/音频放后面？
6. 笔记 AI：确认全部删除，只保留“引用到对话”？
7. 版本保留：手动版本永久保留，自动检查点保留最近 N 个（建议 30 个）？
8. 垃圾桶：30 天自动清理，是否要“清空垃圾桶”二次确认？

这些确定后，再按 Stage 0 开始写代码。
