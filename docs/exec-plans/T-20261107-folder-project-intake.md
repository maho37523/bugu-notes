# T-20261107：项目内嵌套文件夹与工作区入口

日期 / 状态 / 负责人：2026-11-07 / 待决定（需求草案）/ 本会话 Codex；仅需求整理，已停止写入

## 原始诉求

> 我对现在的文件夹项目关系有点不满意，我希望文件夹应该是隶属于项目的，而不是各个项目共享，然后各个文件夹应该是可以嵌套的，最好可以增加查看文件夹结构的功能，就像是vscode里面一样，或者obsidian里面一样。现在的新增按钮的位置我也觉得逻辑不对。项目应该是居中的，然后logo应该有深色模式，不然会割裂。

## 现状证据

- Android 是当前原生实现，`prototype/` 是独立模拟演示；本需求以 Android 为默认讨论对象，待用户确认是否同时调整原型。
- `FolderEntity` 仅有 `id/name/sort/archivedAt`，没有项目归属和父文件夹字段；`NotesDao.observeFolders()` 返回全局列表，`NotesRepository.createFolder()` 创建文件夹时未传项目。笔记和对话自身已有 `projectId`、`folderId`，因此项目切换后仍复用同一文件夹集合。
- `LibraryScreen` 在资料库根级显示平铺文件夹行；尚未发现可展开树形文件夹导航。
- 顶栏“新建”按钮位于搜索按钮旁，菜单提供新建笔记、对话和文件夹；文件夹创建动作未显示项目/父文件夹选项。
- `DshWordmark()` 将品牌图置于固定浅绿底容器，主题可切换明暗，但该容器颜色不随主题变化。
- 项目“居中”的具体对象和页面位置尚不明确，需产品确认；不从旧 Web 演示推断其为当前 Android 行为。

## 目标与范围草案

让每个项目拥有独立的文件夹树，用户可在当前项目中创建、嵌套、浏览文件夹，并让项目入口、内容新增入口和品牌标识在明暗主题下保持清晰一致。仅覆盖经确认的平台与导航页面；不预设数据库方案、视觉稿或批量迁移策略。

## 待确认的产品选择

1. **项目范围与归属**：是否只做 Android 原生，还是 Android 与 Web 演示都要同步？现有“全局/未归属项目”的笔记、对话和文件夹应保留全局区、归入某个项目，还是暂不迁动并提供明确去处？
2. **“项目应该是居中的”含义**：你指主界面顶部/导航中的项目切换器居中，还是项目列表/项目工作区在布局中居中？若方便，请描述你希望它相对哪些元素居中。
3. **新增按钮逻辑**：希望新增入口放在哪个区域、何时显示哪些动作？可接受的初始解释是：在当前项目/文件夹上下文中提供新建笔记、对话、文件夹，并自动归属当前项目与父文件夹；是否符合你的意思？
4. **文件夹树行为**：树状浏览是否应始终显示在侧栏，并支持折叠/展开、进入文件夹与在选中目录下新建子文件夹？VS Code/Obsidian 是交互参考，不自动要求拖放、文件系统同步或快捷键。
5. **项目间移动与删除**：是否允许把整个文件夹子树移动到另一项目？删除项目或文件夹时，现有笔记/对话的归属和恢复行为应怎样处理？这些涉及数据兼容与避免内容丢失，不能默认决定。
6. **Logo 暗色适配**：目标是暗色主题下更换/反转品牌图，还是使用透明底并调整周边留白/颜色？是否有已批准的暗色品牌原图；当前原始设计资产需保护，不能擅自覆盖。

## 验收条件草案（待确认后转为实施标准）

- 在不同项目间切换时，只展示该项目及其全局区约定下的文件夹；同名文件夹可分别存在且定位明确。
- 当前项目内可创建顶层及子文件夹，树形结构能展示父子层级；折叠/展开和进入内容后返回路径一致。
- 在文件夹内创建的笔记/对话归属按确认的项目与文件夹规则保存；已有全局内容按确认方案仍可访问。
- 移动、归档、删除、恢复及项目切换不导致内容悄然丢失或跨项目串用；历史库/备份兼容策略经单独验证。
- 新建入口在用户指定位置，所提供动作和默认归属符合当前项目上下文；空项目、全局区和无当前文件夹状态有清晰行为。
- 暗色及浅色主题中 logo 与其容器、背景对比协调，品牌原图不被覆盖；主题切换后无需重启即可正确显示。
- 若同步调整 Web 原型，明确标注其为演示，不据此宣称 Android 已实现。

## 风险与不做项

文件夹归属/父子关系会触及 Room schema、旧数据映射、备份格式、笔记与对话关联、删除/移动及跨项目上下文边界。当前 schema 8，历史迁移和备份兼容必须先评估；不把所有既有文件夹自动认定为任何一个项目的内容。当前明暗切换存在，但其持久性与设备视觉效果未由本需求核实。此次不实施代码、不迁移数据、不修改依赖或架构、不替换品牌原图，也不对真实数据执行操作。
