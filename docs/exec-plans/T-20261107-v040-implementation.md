## C01：兼容契约与剩余保护证据（以下为实施前静态基线记录）

已核对当前源码：`NotesDatabase` 为 schema 8，保留 1→8 迁移；`FolderEntity` 无项目与父目录；备份 format 为 1，恢复接受 databaseVersion 6 至当前版本。笔记和对话的 `moveToFolder` 目前只检查目录是否存在，非法 ID 会转为 null。新模型需检查每个写入入口并事务重验 scope，而非只过滤 UI。

建议保留计划中确定性拆分：扫描笔记、会话和临时草稿（含隐藏状态），每个旧目录按引用 scope 生成根目录；全局优先保留旧 ID，否则按项目 ID 稳定排序首项保留。其余 ID 必须确定性生成、检查碰撞并确定性重试；悬空引用或项目不合法时停止并回滚。目录以外的正文、消息、附件、快照、时间戳及行数保持不变。SQL 升级与旧 ZIP 规范化使用同一套合成输入核对映射。

初步写入点盘点（尚须沿 DAO 和 UI 调用链复核）：

- `NotesRepository` 的导入、新草稿、创建、保存、移动项目、移动目录、目录创建/归档/删除，以及 `MarkdownImportService` 转发链；其中部分输入当前会静默置空。
- `ChatRepository` 的临时草稿保存、首条消息提交、会话创建、移动目录和项目；首条提交当前只检查目录存在。
- `ProjectsRepository` 的项目删除及项目相关 DAO 批量写入；必须核对归档、回收站和临时草稿。
- `BackupService` 的导入规范化、引用检查和事务恢复；`NotesDatabase` 的新旧 schema 与迁移。界面捕获、迟到回调、内存草稿和直接 DAO 调用仍需逐项核对。

### 拆分 ID 的可审查候选契约

按当前集成源码候选新增 schema 9；format 保持 1、databaseVersion 写 9。正式编码前重新检查 v0.3.0 集成基线，若该基线已使用 9 则顺延并同步版本矩阵。保留既有 `folders` 的四列，增加可空 `projectId` 和 `parentId`，增加匹配 Room 新建库的项目/父目录索引；具体 DDL 须以 Room 生成结果逐列及索引实测为准。

候选克隆 ID 规则：先保留全部旧文件夹 ID，不论之后由哪个 scope 使用；文件夹按其 ID 的 UTF-8 字节顺序处理，项目 scope 按项目 ID 的 UTF-8 字节顺序处理。保留旧 ID 的规则为全局优先，否则首个项目；其余克隆按 `folder-v1-` 加 SHA-256 小写十六进制生成。哈希输入是 UTF-8 的 `bugu-folder-v1`、旧 ID、项目 ID 和十进制重试序号，每项前缀为四字节无符号大端字节长度；序号从 0 开始。候选与任一旧 ID 或已生成 ID 相同则增加序号重试；不存在靠哈希值大小分配保留 ID 的行为。Room 与备份转换必须共享该精确约定和测试向量；此处仅是方案，还未实现或验证。

2026-11-07 用 Python 标准库对合成字符串计算候选编码向量（不是生产迁移测试）：`D/A/0` → `folder-v1-e9ca76675865f1bf44351c0996b19a538c2452414e13672083ff2c8e07ebbf15`；`D/A/1` → `folder-v1-019d9946f75d20153ae5d206031c6edf5d8e9788180560576ea4bfad7ff4f7d4`；`资料/项目/0` → `folder-v1-6521099e4b4cbc8526b6a20bbaee2d165b05f80a14e3a239ecd65ad56ca2dab9`。项目及重试序号变化结果不同；实际碰撞分配、跨实现一致性和事务回滚尚未验证。

处理顺序为：读取并验证所有项目、目录、引用与临时草稿 scope；内存建立完整映射并检测碰撞；在单一事务中添加结构、插入克隆、仅重写对应引用、验证计数与同 scope 不变量；失败回滚整个迁移，不启用破坏性重建。旧 ZIP 先完成 6→8 缺列规范化，再执行同一映射和验证，全部检查通过后才进入既有附件暂存和数据库事务。恢复失败维持原数据库和附件；导出仍排除 API 配置。

发现一个实际兼容边界：旧版删除项目并不删除该项目的临时草稿；`ChatRepository` 还专门允许全局区取回孤立草稿，现有 lifecycle 回归覆盖这个路径。旧备份关系检查也允许临时草稿引用不存在的项目。因而孤立草稿不能直接判为“旧版不可能的数据”，更不能为通过迁移而丢弃或覆盖全局草稿。当前确认的失败保护规则意味着遇到此情况应保留原库并停止迁移；还需要设计用户可理解的安全处置和合成测试，才能声称兼容方案完整。

回退分两种：开发候选只撤销本任务增量并保留 v0.3.0 未提交更改；真实升级前须在隔离环境验证旧版备份可恢复，并保留升级前归档、附件和匹配的安装身份/签名。新库不能直接用旧 APK 打开，回退到升级前归档会丢失升级后产生的改动；当前没有真实数据备份或恢复演练证据。不得以本节取代实际演练或真实数据操作的单独授权。
