# T-20261107：OpenAI 订阅模型官方接入需求

日期：2026-11-07；状态：需求草案（目标已收窄，官方资格与实施范围待核）；负责人 / 集成人：未认领；本次仅需求整理。

## 原始诉求

> 现在就只完成一个目标，让软件可以接入openai的订阅模型调用，用官方的方式。

## 目标与范围

唯一产品目标：让布谷笔记在满足 OpenAI 官方资格及授权条件时，通过 OpenAI 官方认可的授权和推理路径，使用用户已有 ChatGPT 订阅所允许的模型能力。

“官方的方式”暂按以下可验证含义理解：使用 OpenAI 为该用途公开或明确批准的客户端注册、用户授权、令牌生命周期及模型推理协议；仅向官方规定的 OpenAI 主机发送订阅授权凭据；遵守授权范围、套餐限制、模型权限和 UI 要求。不得把网页私有接口、Cookie/会话令牌抓取、密码收集、伪装 API Key 或未经批准的应用身份称为官方接入。

本需求只针对 OpenAI / ChatGPT 订阅路径。现有 v0.3.0 OpenAI API Key 能力与本需求不同，不因已有 API 支持而视为满足。Anthropic/Claude、其他厂商、订阅福利兑换 API credits、API Key/BYOK、计费购买/余额管理、搜索/工具调用、代理服务和多厂商路由均不属于本目标。

目标平台暂按现有 Android 原生应用理解；分发方式、应用是否满足官方接入资格，以及该授权预览是否允许 Android 客户端仍待核实。因此目前不承诺目标一定可实现。若当前资格或平台规则不允许，应明确记录官方阻塞及可恢复条件，不以技术绕行替代。

## 建议验收条件（待用户确认及可行性核查）

1. 用户能从应用发起 OpenAI 官方规定的授权流程；成功后应用清楚显示授权账号/连接状态及其凭据来源为 ChatGPT 订阅授权，而非 API Key。
2. 授权后的聊天请求按 OpenAI 当前官方订阅接入规范发送到规定端点，采用规定的模型发现、请求字段、流协议及终态判定；不得静默转用 API 端点、其他账号、API Key 或收费来源。
3. 用户取消、拒绝授权、无资格、模型不可用、达到套餐限额、授权过期/撤销、刷新失败、网络中断及流中失败时，有明确状态；不把部分流输出报告为成功，已有聊天正文/草稿不丢失。
4. 账号令牌按官方要求安全存储、刷新、隔离及注销；授权 code/token 不进入日志、备份导出或用户可见诊断；请求只发往官方允许主机。
5. 只暴露该官方订阅预览当前支持的模型和能力，并按官方 UI/品牌要求呈现；不承诺 API Key 路径专属功能适用于订阅路径。
6. 离线合成回归覆盖授权状态机、取消/失败/刷新竞争、账号隔离、官方主机限制、Responses 流成功/失败/截断及兼容既有本地聊天；在线和设备验收分别记录，不用 fixture 或 HTTP 200 替代。
7. 现有 API Key、DeepSeek/百炼、自定义连接、笔记/对话/项目、数据库 schema、业务备份及附件行为保持兼容；除非后续经审查确认不可避免，不能把数据库/备份迁移暗含在本目标中。

## 风险与边界

- 官方接入资格可能与开源、托管、收费及分发形态有关；项目当前分发资格、适用地区及测试账号状态均未在本次核实。
- 官方方案曾要求特定客户端注册、PKCE/状态校验及 loopback 回调；Android 浏览器回调和进程生命周期还未通过官方适用性确认或隔离验证。不得擅自换成 WebView、私有 scheme 或复用其他客户端 ID。
- 订阅套餐的额度与 API 组织账单不同；请求不应在订阅失败时自动降级到 API 付费路径。该目标不包括查询精确余额或保障不限量。
- OAuth 刷新、注销、备份排除与 Keystore 故障涉及新增敏感凭据；需先完成安全设计及合成验证。不得读取真实凭据或对真实账号做未获准测试。
- 官方预览规则、资格、模型列表和协议可能变化。实施前重新核对官方一手资料，记录访问日期、版本和资格依据。
- 代码目录内存在 v0.4.0 进行中任务；按项目规则，同一工作目录写入必须串行。后续实施前须先确认该会话已释放共享写入范围。
