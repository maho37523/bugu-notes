# v0.1.9 · 统一资料库与创建生命周期

本轮由主代理制定产品规则与验收，GPT-6 Luna 执行实现和打包。

## 产品规则

1. 用统一资料库替代笔记/对话两个顶层板块。主页以文件夹和内容列表为主体，提供“全部 / 笔记 / 对话”筛选；点内容进入编辑器或对话。
2. 顶部只有一套范围、搜索、新建操作。新建菜单包含笔记、对话、文件夹；笔记列表不再额外占一行操作栏。
3. 侧栏承载资料库、类型筛选、归档、回收站等导航，不再塞入历史对话。底部唯一“全局设置”处理 API、外观、数据和记忆。当前类型筛选延续到归档/回收站。
4. 文件夹可以混合收纳笔记和对话；内容菜单支持移动到文件夹、归档、移到回收站。删除文件夹只解除归属，保留内容；长按/更多菜单行为一致。
5. 归档与回收站共用列表。笔记和对话都支持归档恢复、移到回收站恢复、确认后永久删除。原有聊天归档数据保留。
6. 新笔记在有正文或用户填写了非空标题时才保存。在同一次新建编辑中，如果正文被全部删除且没有主动命名，清理该新笔记及其派生数据；不改变旧笔记的空白编辑行为。
7. 新对话进入临时编辑页，不创建 chat_sessions 记录，不出现在资料列表。未发送正文、引用和附件单独保存，返回列表后再新建可恢复；按项目范围隔离。首条消息验证和上下文构建成功后，原子创建真实对话并清除对应临时草稿。
8. 笔记预览保留原文的换行、空行、列表和代码块；不会把不同段落拼接在一起。编辑与预览继续使用相同语法规则，保存原始 Markdown。
9. 排版统一采用自适应宽度、可收缩标题、44dp 点击区、可滚动筛选和工具栏，避免小屏、长标题、键盘弹出时错位。

## 实现边界与数据

- 升级到 Room 7：笔记归档字段、对话文件夹/回收站字段、独立临时对话草稿表；保留所有旧内容和命名。
- 备份覆盖新增字段与临时草稿；旧 v0.1.8 备份经过显式兼容转换后仍能恢复。
- 删除、归档及列表查询排除临时会话；已有无消息的旧空白会话不破坏性清理。
- 版本 0.1.9，versionCode 11。保留旧 APK。

## 验收

- 主入口没有重复创建栏，资料列表可混合显示/筛选笔记与对话，文件夹能容纳两种内容。
- 创建空笔记退出无列表记录；输入后清空且未命名退出也无记录；主动命名的空笔记与已有笔记保留。
- 新对话输入后返回不新增列表记录，再次新建恢复输入；首次发送才创建一个真实对话。
- 统一归档/回收站支持两种类型恢复与永久删除，永久删除有确认。
- 原数据库迁移、旧备份兼容、新备份往返、临时草稿提交和 Markdown 换行检查通过。
- 完成 assembleDebug、lintDebug、APK 版本与签名核验；记录无法覆盖的真机/API 测试。
